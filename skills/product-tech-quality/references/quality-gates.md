# 质量门禁与发布门禁

## 质量门禁（按需裁剪，裁掉的写明原因）

| 门禁 | 最低证据 |
| --- | --- |
| 功能 | 核心流程逐条真实走通，有截图或日志 |
| 边界 | 空输入、超长输入、并发、网络失败、上游超时 |
| 真实能力 | 用正确请求体发真实业务请求，不只看健康检查（P2） |
| 性能 | 关键接口的耗时分布和资源占用，有基线对比 |
| 安全 | 凭证不落盘不打印、权限最小、输入校验、依赖漏洞 |
| 计费 / 账务 | 扣费与结果一致；失败、超时、重试不重复扣费（P6），逐笔核对样本 |
| 可观测 | 出问题时能定位到哪一层（日志、请求 ID、监控） |
| 回滚 | 回滚步骤写清楚并演练过，或说明为什么无法演练 |
| 文档 | README / runbook 记录路径、配置、验证方法和已知问题 |

## 发布门禁结论

```markdown
**发布门禁**：通过 / 有条件通过 / 不通过

- 已验证：……（证据）
- 未验证：……（原因、风险）
- 条件：（有条件通过时必须写）
- 回滚方案：……
- 上线执行：交老十（ops-management），按盘点 → 备份 → canary → 验证 → 放量
- 需要授权的事：……
```

任何一项"计费 / 账务"或"回滚"缺失证据，结论不能是"通过"。
