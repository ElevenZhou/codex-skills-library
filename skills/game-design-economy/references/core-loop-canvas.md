# 核心循环画布

复制到 `design/core-loop.md` 填写。不知道的写"未知，待验证"并列入假设清单。

```markdown
# <游戏名> 核心循环画布

## 三层循环
| 层 | 时长 | 玩家动作 | 即时反馈 | 获得 | 再来一次的理由 |
|---|---|---|---|---|---|
| 微循环 | 5-30 秒 | | | | |
| 局循环 | 1-5 分钟 | | | | |
| 日循环 | 当日 | | | | |
| 周/元循环 | 一周以上 | | | | |

## 资源表
| 资源 | 类型(软/硬/体力/碎片) | 来源 source (量/频率) | 去向 sink (量/频率) | 上限/过期 | 可购买 |
|---|---|---|---|---|---|

检查: 每个 source 有 sink? 每个 sink 有 source? 是否存在无限囤积的资源?

## 玩家动机
- 主要驱动: 掌握(技巧) / 收集 / 进度 / 表达 / 竞争 / 社交  (选 1-2 个)
- 压力与释放节奏: <紧张-放松怎么交替>
- 失败的代价: <损失什么? 是否可接受>

## 风险点
| 风险 | 表现 | 验证方式 |
|---|---|---|
| 无聊点 | 局循环第 N 分钟无新信息 | G2 试玩观察 |
| 卡关点 | 资源买不起下一级 | economy_sim stalled% |
| 通胀 | 货币囤积 p90 持续上升 | economy_sim bal_p90 |
| 逼氪感 | 免费路径低于 X% 进度 | 软启动付费前后留存 |

## 微创新 (≤3)
| 点 | 针对的痛点 | 失败时退回什么 |
|---|---|---|
```

## 检查

- 微循环必须在 30 秒内有一次正反馈（得分、数字跳动、音效、进度条），否则 G2 试玩中会表现为"不知道在干嘛"。
- 局循环结束要有一个明确的"下一步"按钮或悬念（差一点、下一关预览、可领取奖励）。
- 日循环不能只靠"签到奖励"：要有当天才能完成的小目标。
