# 留存钩子

参考值，按品类校准。每个钩子都要有埋点（见 `game-playtest-qa/references/telemetry-spec.md`），上线后用实测验证有没有用。

## 层次

| 层 | 钩子 | 目的 | 设计要点 |
|---|---|---|---|
| D0（首次会话） | 教学即玩；3 分钟内第一次升级/解锁；首个小目标 | D1 留存 | 首局无失败；首个奖励在 60 秒内；结束时展示"明天有什么" |
| D1–D3 | 每日登录奖励、每日任务、限时挑战、体力恢复 | 习惯 | 奖励递增但不惩罚断签；任务当天可完成（10 分钟内） |
| D3–D7 | 连续登录（streak）、成就/收集册、章节解锁 | 中期目标 | streak 断了给补签（看广告或小额付费），降低挫败 |
| D7–D30 | 元成长（转生/赛季/收集系统）、活动、排行 | 长线 | 内容更新节奏（每周至少一个小活动） |
| 社交（可选） | 好友排行、分享奖励 | 获客与留存 | 不强制；注意隐私和合规 |
| 通知 | 本地推送（体力满、奖励可领） | 召回 | 获得授权后；每日 ≤1–2 条；可在设置中关闭 |

## 签到奖励曲线示例（7 天）

第 1 天小奖励，第 3、7 天大奖励；总价值约等于 1–2 天自然产出（参考值）。用 `economy_sim.py` 的 `daily_sources` 建模，看对 D7 里程碑到达时间的影响。

## 设计检查

1. 每个钩子回答："玩家今天回来的具体理由是什么？"
2. 拉长而非惩罚：断签不清零（或给保护/补签）。
3. 不要把所有钩子堆在 D1：D3、D7、D14 各留一个新奇点。
4. 钩子的成本进经济表：奖励是产出，进 `daily_sources`。
5. 通知和弹窗有频次上限；新手期不弹推销窗口。

## 验证

| 假设 | 指标 | 方法 |
|---|---|---|
| 每日任务提升 D1 | D1 留存 A/B | 软启动分流（远程开关） |
| streak 提升 D7 | D7 留存 / 连续天数分布 | 埋点 `streak_day` |
| 推送提升召回 | 推送点击率、召回 DAU | 埋点 `push_open` |

样本量不足时只写"方向性"，不做结论（`game-playtest-qa` 的软启动阈值章节）。
