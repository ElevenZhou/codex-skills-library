# Comparison Scorecard

Verify behavior before scoring. Use a 1-5 scale and support every score with a concrete observation.

## Criteria

| Criterion | Core question |
| --- | --- |
| Domain specificity | Does the interface visibly belong to this product and audience? |
| Information hierarchy | Can users identify risk, status, and next action quickly? |
| Visual authorship | Are composition, typography, color, and material intentional? |
| Interaction completeness | Are states, feedback, keyboard behavior, and recovery coherent? |
| Responsive recomposition | Does mobile preserve priority rather than merely stack? |
| Anti-template quality | How much generic hero/card/pill/gradient structure remains? |
| Long-session usability | Will density, contrast, and motion remain tolerable over time? |
| Technical quality | Are resources, console, overflow, layout stability, and performance sound? |
| Asset integration | Do images reveal the subject without obscuring controls or text? |

## Scale

- **1**: fails the product task or contains blocking defects
- **2**: usable only with significant redesign
- **3**: competent but generic, incomplete, or weakly matched to the domain
- **4**: strong, coherent, and production-credible with minor limitations
- **5**: exceptional fit with clear authorship, complete behavior, and verified polish

## Evidence

Record:

- desktop and mobile screenshots
- critical interaction results
- console and resource status
- horizontal overflow measurements
- asset sizes and load results
- the highest-impact refinement made after the first screenshot

## Recommendation Rules

- Do not total scores blindly. Some criteria matter more for the product.
- Name category winners where useful: best for endurance, emergency response, spatial reasoning, trust, or memorability.
- Prefer the direction that improves the primary job without creating new operational risk.
- Explain why visually dramatic alternatives lost.
- Keep the baseline in the report even when it does not win.
