# Nightline Case Study

The Nightline city safety dashboard is the first validated Interface Prism experiment.

## Shared Product Contract

- audience: city night-transit operators
- first-screen goal: understand risk and the next action within ten seconds
- fixed metrics: 42 active routes, 7 open alerts, 96% safe arrival, 4m12s response time
- fixed interactions: region, shift, severity filter, incident acknowledgement, simulated-alert dialog
- fixed viewports: 1440 x 900 and 390 x 844
- fixed stack: standalone HTML, CSS, and JavaScript with no paid runtime

## Directions

1. `Minimal Civic`: a quiet ruled ledger optimized for long-session clarity.
2. `Industrial Command`: a dense hard-edged command surface optimized for incident recognition.
3. `Cartographic Night`: a generated city map plus HTML field ledger optimized for spatial reasoning.
4. `Advanced v1`: balanced general-purpose baseline.
5. `Standard v1`: familiar dashboard baseline.

## Findings

- Minimal Civic won long-session calm and information cleanliness.
- Industrial Command won urgency recognition and operational density.
- Cartographic Night won domain identity and spatial reasoning.
- Advanced v1 remained the strongest balanced default.
- Standard v1 stayed useful as a fair, polished conventional baseline.

All new variants passed desktop/mobile screenshots, critical interactions, console checks, and horizontal-overflow checks. The generated map was reduced from about 3.8 MB PNG to about 481 KB WebP before final verification.

## Reuse Lessons

- Keep product behavior shared and visual composition isolated.
- Give specialist directions permission to change silhouette, not only tokens.
- Preserve the baseline and verify it with the same rigor.
- Use generated imagery only when it changes product comprehension.
- Recommend by operating context instead of declaring one universal winner.
