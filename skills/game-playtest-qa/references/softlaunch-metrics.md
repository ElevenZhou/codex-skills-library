# 软启动指标与判读

阈值**参考值，按品类校准**；与 `game-dev-workflow/references/stage-gates.md` 的 G5 表一致，此处补充判读方法。

## 先看样本量

| 指标 | 最少样本（每个变体/每个渠道） | 说明 |
|---|---|---|
| CPI | 数百安装 | 看趋势，单日噪声大 |
| D1 留存 | ≥ 500–1000 安装 | 95% 误差约 ±3–4 个百分点 |
| D7 留存 | ≥ 1000+ 安装，且安装满 7 天 | 不满 7 天的队列不要计入 |
| ARPDAU / 付费转化 | 视付费率而定，付费用户数 ≥ 数十 | 付费用户少时只能写区间 |
| A/B | 每组千级起 | 差异小于误差就写"无显著差异" |

留存误差估算：`±1.96 × sqrt(p(1-p)/n)`。例：n=1000，p=0.35 → ±3.0 个百分点。

## 门槛（再次列出，便于对照）

| 指标 | 超休闲 | 休闲/混合 | 中度 |
|---|---|---|---|
| D1 留存 | ≥ 35% | ≥ 35–40% | ≥ 38–42% |
| D7 留存 | ≥ 8% | ≥ 12–15% | ≥ 15–20% |
| D30 留存 | — | ≥ 4–6% | ≥ 7–10% |
| 日均时长 | ≥ 8 分钟 | ≥ 15 分钟 | ≥ 25 分钟 |
| CPI | < $0.3 | $0.5–1.5 | $2–5 |
| ARPDAU | ≥ $0.08 | $0.05–0.20 | $0.15–0.5+ |
| 预测 D7 LTV / CPI | ≥ 1.1–1.3 | 同 | 同（视回本周期） |

地区、系统、渠道影响极大（欧美高于东南亚；iOS 高于 Android）；对比用同地区同渠道同期数据。

## 判读顺序（先诊断再动手）

1. **数据可信吗？** 埋点是否全覆盖、`telemetry_lint.py` 通过；安装数与商店后台是否对得上；是否混入内部测试用户。
2. **流量是否匹配？** 素材承诺的玩法与实际一致吗？不一致会得到"低 CPI、低 D1"的假象。
3. **漏斗在哪断？** 安装 → 启动 → 新手开始 → 新手完成 → 第一局完成 → 第二局开始 → D1 回访。最大跌幅处就是首要问题。
4. **分群**：按渠道、地区、设备档位、系统版本看留存；崩溃集中在低端机会拉低整体数据。
5. **对 LTV**：用 D1/D7/D30 拟合留存曲线外推，乘 ARPDAU；写明置信区间。
6. **决策**（沿用 G5 分流表）：
   | 结论 | 条件 | 动作 |
   |---|---|---|
   | 放量 | 预测 D7 LTV ≥ CPI×1.2 且崩溃/ANR 达标 | 逐步加预算，每次 +20–30%，观察 3 天 |
   | 优化后复测 | 单项未达标且原因明确 | 改一件事，复测 |
   | 回 G3 | D1 或 D7 明显低于门槛且漏斗断点在玩法 | 改循环/新手/难度 |
   | 回 G2 | 新手完成率和首局完成率就低 | 核心玩法问题 |
   | 终止 | 两轮迭代无改善且超预算 | 按立项止损线执行（CEO 视角） |

## 软启动期间的守则

- 一次只改一件事，用远程配置/版本号标注，记录在 `docs/metrics-log.md`。
- 每日固定时间看一次，不要盯分钟级波动。
- 崩溃率 > 2% 或 ANR > 0.5% 先停投放修稳定性。
- 数据发给负责人时，**首行写结论**，给数字和对照基线，写明样本量与误差，推翻旧判断要明说。
- 重要结论、坏消息按全局约定推送飞书通知（见用户全局 CLAUDE.md），内容不含凭证或原始日志。
