# 观察式试玩脚本（5 人测试）

用途：G2 回答"陌生玩家能不能无提示玩懂并愿意再玩"。**不回答**"能不能赚钱"或"留存多少"。

## 准备

- 招募 5 位符合目标用户画像的人（不是同事、不是开发者、没看过游戏）；若可能再准备 2 人备用。
- 构建：固定版本号；真机（目标档位中端机）；开屏幕录制 + 外放录音（征得同意）。
- 环境：安静、手机正常握持；你坐在旁边，不看屏幕，不说话。
- 预置问卷（试玩后 2 分钟）。

## 主持脚本

开场（念，不加料）：
> "我们在测试游戏，不是在测试你。请像平时玩手机游戏那样玩，想到什么说什么。我不会回答怎么玩，卡住了就按你的想法试。你随时可以停。"

任务：
1. "打开游戏，玩到你觉得想停为止。"（最长 10 分钟）
2. 到 3 分钟 / 6 分钟时记录进度，不干预。
3. 试玩结束后问：
   - "用你自己的话说，这游戏是做什么的？"
   - "刚才最开心 / 最烦的一刻是什么？"
   - "有哪里你不知道该做什么？"
   - "如果它免费，你明天会再来吗？为什么？"（记录原话，不当作留存数据）
   - "你觉得这游戏像哪个游戏？"
4. 打分（1–5）：上手难度、想继续玩的程度、视觉/音效印象。

主持纪律：
- 沉默超过 20 秒才允许说"你在想什么？"，仍不提示操作。
- 卡住超过 60 秒记为"阻塞"，之后可给最小提示并记录。
- 不解释设计意图，不辩解。

## 汇总与判定

| 指标 | 门槛（G2，参考值） | 实测 |
|---|---|---|
| 无提示完成首局 | ≥3/5 | |
| 自愿再玩一局 | ≥3/5 | |
| 一句话复述正确 | ≥3/5 | |
| 阻塞（>60 秒卡住）次数 | 每人 ≤1，且没有同一位置被 ≥3 人卡住 | |
| 想继续玩（1–5）均值 | ≥3.5 | |

- 同一问题 ≥2 人出现 → 记为确认问题，进待优化清单。
- 只有 1 人出现 → 记为"疑似"，下一轮留意。
- 判定后修复，再换 3–5 位新玩家复测；老玩家不再参与同一阶段测试。
- 记录原始证据（录屏文件名），结论写入 `docs/stage-gates-log.md`。

## H5 游戏的补充

用 `playwright` 先跑自动化路径（加载、开始、结算）确保没有阻断性 bug，再让真人试玩；控制台 error 和网络失败要在试玩前清零。

## 局限

5 人只能发现严重可用性问题，不能估计比例。不要在报告里写"60% 玩家喜欢"，写"5 人中 3 人……"。
