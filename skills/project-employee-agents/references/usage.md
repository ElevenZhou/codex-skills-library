# 使用方式

## 默认入口

用户不需要点名岗位。只要描述目标、问题、项目阶段或想要的结果，系统默认由项目经理统筹，并自动激活相关岗位。

推荐说法：

```text
启动项目员工团队，帮我把这个项目从立项前推进到可执行计划。
```

```text
项目员工开工：我们要做一个面向小微企业的 AI 客服产品，请先判断现在处于什么阶段，给出本周工作和管理成果。
```

```text
请用项目全周期管理方式推进这个项目。先做市场、客户、产品和财务判断，再决定是否立项。
```

```text
继续推进项目。读取当前项目文件，判断阻塞点，自动安排需要的岗位，完成后给我状态、风险和需要拍板的事项。
```

## 默认调度逻辑

1. 项目经理读取项目资料，判断当前阶段、目标、范围和缺口。
2. 项目经理自动选择岗位，不要求用户逐个点名。
3. CEO/COO 只在战略、资源、重大风险或流程冲突时参与。
4. 专业岗位提供判断和成果；项目经理合并冲突并形成决策请求。
5. 测试、财务、客户或其他门禁岗位按阶段验收。
6. 系统只向用户汇报：已完成成果、证据、风险、下一步和需要批准的事项。

## 什么时候指定岗位

只有在以下情况才需要点名：

- 你希望绕过完整项目调度，只做一次专项评审。
- 你已经知道需要哪种专业意见，例如“只做财务测算”。
- 你要比较两个岗位的冲突判断，例如“让产品经理和市场经理分别评估”。

例如：

```text
只让财务经理评估这个项目的现金流和止损线，不做其他执行。
```

## 最少输入

不需要一次填完表单。最好提供：项目名称、要达成的结果、当前阶段或已知情况、时间窗口、预算/资源约束、已有文件位置。缺失信息由项目经理列为假设，并安排验证动作。

## 每次默认输出

- 当前阶段和判断依据。
- 本轮启用的岗位及其责任。
- 已完成的管理成果和文件位置。
- 关键事实、假设和置信度。
- 风险、依赖、阻塞和负责人。
- 下一周期任务、验收标准和截止时间。
- 必须由人确认的预算、生产、合同、客户承诺或外部发布事项。

## 项目目录建议

```text
project/
  project-brief.md
  context/
  decisions/
  risks/
  tasks/
  deliverables/
  reviews/
  memory/
```

项目资料放在当前工作区或明确的项目目录里。下一次只需说“继续推进项目”，系统就可以沿用简报、台账、决策和记忆。
