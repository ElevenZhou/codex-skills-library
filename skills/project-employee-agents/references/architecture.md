# 从 Markdown 到可运行员工 Agent

Markdown 角色卡是员工的认知层和行为契约，但不是完整运行时。一个可持续工作的员工 Agent 至少由六层组成：

| 层 | 作用 | 典型内容 |
| --- | --- | --- |
| 角色认知 | 决定岗位如何判断和表达 | 使命、经验、态度、边界、技能包 |
| 项目上下文 | 让角色知道当前业务 | 简报、阶段、指标、客户、约束、历史决策 |
| 工作技能 | 让角色能完成具体动作 | 搜索、文档、表格、代码、浏览器、CRM、广告、财务计算 |
| 控制器 | 决定谁在什么时候做什么 | 阶段路由、任务分解、依赖、审批、重试、升级 |
| 状态与记忆 | 让团队连续工作 | 任务台账、决策记录、风险、客户反馈、指标、复盘经验 |
| 验收与观测 | 判断工作是否可信 | 输出评分、测试、日志、成本、耗时、人工审核、回滚 |

## 推荐的最小运行模型

```text
用户目标
  -> 项目经理创建简报和阶段
  -> 控制器选择岗位与技能
  -> 岗位读取项目上下文并产出成果
  -> 项目经理合并冲突并提出决策
  -> CEO/COO 或人类在权限边界内批准
  -> 执行工具完成任务
  -> 测试/财务/客户等岗位验收
  -> 状态台账、指标和记忆更新
  -> 进入下一阶段或回到前置验证
```

## 权限分级

- 自动允许：阅读项目文件、分析数据、生成草稿、创建任务、更新非生产台账。
- 人工审批：发送外部承诺、发布内容、修改生产环境、启停投放、改变预算、接受合同、触达客户。
- 禁止：索取或写入密钥、绕过权限、删除不可恢复数据、把未经证实的判断写成事实。

## 与现有技能的连接

- `auto-loop`：提供感知、规划、执行、验证、改进和交付循环。
- `agent-scaffolder`：把本技能的角色、工具、状态和权限整理成可运行 Python Agent 项目。
- `production-agent-architecture`：补充生产级上下文、观测、评估、权限和发布设计。
- 具体工具技能：提供浏览器、文档、表格、广告、部署、消息等实际动作。

先用 Markdown 迭代岗位和流程，等重复场景稳定后再把高频动作接入控制器。这样可以先验证岗位设计，再投入运行时开发。
