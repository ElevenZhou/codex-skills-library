# Slide Patterns

Use these patterns as building blocks, not templates to repeat mechanically.

## Cover

- Large product/company name.
- One-line positioning.
- One strong image or visual field.
- Minimal metadata.
- Avoid cramming agenda, team, and feature list.

## Chapter Divider

- Large number.
- Short section title.
- One sentence explaining the section's purpose.
- Distinctive but consistent rhythm.

## Product Form

- Screenshot, mockup, or product UI diagram.
- 3-4 callouts around the visual.
- Explain how the user operates the product.

## Workflow

- 5-8 steps max.
- Use one highlighted step to show current focus.
- Add a note about human control or governance if relevant.

## Capability Matrix

- Rows: capability domains.
- Columns: current capability, next enhancement, user value.
- Keep text short; use bold row labels.

## Architecture

- Use layers when explaining systems.
- Put user/workflow at top and data/infrastructure at bottom.
- Show trust/security boundaries explicitly.

## Market Inevitability

- Use force diagram, flywheel, value chain shift, or before/after operating model.
- Avoid unsupported market-size numbers unless sourced.
- Anchor the argument in structural forces.

## Business Model

- Use a table with mode, customer, revenue logic, deployment fit.
- Keep it factual and adaptable.

## Roadmap

- 3-5 phases.
- Each phase has goal and deliverable.
- Avoid listing every engineering task.

## Closing

- Resolve the opening tension.
- State the recommended next action.
- Do not end with only "Thank you".
