# Deck Contract

Use this for any substantial deck before authoring slides.

## Contract Fields

- **Audience:** who will read or watch the deck.
- **Decision/job:** what the deck should make them understand, believe, decide, or do.
- **Central claim:** the one idea the audience should retain.
- **Source base:** files, project docs, data, screenshots, prior decks, web sources, and assumptions.
- **Deliverables:** PPTX count, visual alternatives, graphics, PDFs, screenshots, zip files.
- **Constraints:** brand, language, forbidden phrases, confidentiality, deadline, tool path, output location.
- **Visual ambition:** conservative, premium consulting, product-system, cinematic, technical, investor, etc.
- **Acceptance checks:** slide count, required sections, required graphics/tables/charts, render QA, no overflow.

## Communication Job Template

By the end, this audience should **[understand/believe/decide/do]** **[specific outcome]** because **[reason/evidence]**.

## Assumption Policy

Use explicit assumptions when details are absent:

- Product names, visual directions, market framing, and example metrics may be proposed.
- Do not invent customer names, signed contracts, revenue, regulatory approvals, case results, or factual market numbers.
- Use "proposal", "target", "illustrative", or "recommended" when evidence is not source-backed.

## Deliverable Modes

- **Single polished deck:** best when the user chooses a style or needs one final artifact.
- **Four visual directions:** best for early brand exploration or when the user asks for alternatives.
- **Deck plus graphics pack:** best when diagrams need reuse in PPT, website, or sales material.
- **Source refresh/edit:** best when there is an existing PPTX or brand template.
