# 阶段门禁（stage gates）

所有数值是**参考值，按品类校准**（品类、地区、渠道、买量来源不同差距很大）。门槛应在进入阶段**之前**写下来，不要看到数据再定。

判定格式：

```markdown
## Gate G? 判定 <日期>
结论: 通过 / 有条件通过 / 不通过
| 指标 | 门槛 | 实测 | 样本量 | 来源 |
|---|---|---|---|---|
遗留风险: ...
下一步: ...（若不通过：回到哪个阶段、改什么、最多再试几轮）
```

## G0 立项/定位

| 检查项 | 通过标准 |
|---|---|
| 对标 | 1–3 个，各有市场证据（榜单排名/下载量/评论数/收入估算），记录来源和日期 |
| 差异点 | ≤3 个，每个能用一句话说明对玩家的好处 |
| 预算与止损 | 人天/现金上限；G2 未过时的明确动作 |
| 引擎 | 已选并写明理由（`engine-choice.md`） |
| 合规前置 | 目标地区、主体、是否需要版号/分级已知（`monetization-compliance.md`） |

不通过：缺证据的对标补证据；预算算不出来就先做一个 3 天的原型探路。

## G1 一页纸 + 核心循环

| 检查项 | 通过标准 |
|---|---|
| 一页纸 | 模板 13 节无空项（可写"未知，G2 验证"） |
| 讲得清 | 向 3 个没听过的人用 30 秒讲，≥2 人能复述核心玩法 |
| 再来一局 | 有具体机制，且可在原型里测 |
| 数值骨架 | 有主要货币的来源/去向表（`game-design-economy`） |

## G2 垂直切片（先能玩，再好看）

灰盒美术即可。切片 = 一整个核心循环 + 一个最小成长/结算，不是一关精修。

| 指标 | 门槛（参考值） | 如何测 |
|---|---|---|
| 无提示完成首局 | ≥3/5 人 | 5 人观察式试玩（`game-playtest-qa` 的试玩脚本） |
| 自愿再玩一局 | ≥3/5 人 | 首局结束后不催促，记录是否主动再来 |
| 首局时长 | 在设计范围 ±30% | 计时 |
| 帧率（目标机） | ≥55 fps 稳定（60 fps 目标） | 真机或最低配参考机 |
| 崩溃 | 0 | 试玩期间 |
| 数据驱动 | 关键数值在配置文件，不在代码里 | 代码走查 |

不通过：最多再迭代 2 轮；仍不过，换玩法或砍项目。**不要用美术补玩法。**

## G3 生产

| 指标 | 门槛 |
|---|---|
| 内容/系统清单 | 100% 实现，P0/P1 缺陷清零 |
| 自动化 | 冒烟 + 核心逻辑测试全绿（Godot: `godot --headless -s tests_dev/...`） |
| 数值模拟 | 经济模拟显示 D1–D30 无硬卡点（stalled% 在目标内，见 `game-design-economy`） |
| 性能预算 | fps / 内存 / 加载 / 包体在预算内（`game-playtest-qa`） |
| 埋点 | 核心漏斗事件 100% 覆盖，`telemetry_lint.py` 通过 |
| 里程碑 | 沿用 M0–M5 的纪律时见 `rebuild-dev-milestones` |

## G4 内测 / 真机

| 指标 | 门槛（参考值） |
|---|---|
| 设备矩阵 | 低/中/高端 + 不同 Android 版本各至少 1 台通过全流程 |
| 崩溃率 | 会话崩溃率 < 1%，ANR < 0.3%（内测样本） |
| 首次加载 | 中端机冷启动到可玩 < 5 秒（休闲类） |
| 包体 | 在目标预算内（休闲 < 80 MB 常见，超休闲 < 30 MB） |
| 签名包 | 真机安装/启动/完成一局（`rebuild-build-release`） |
| 埋点验证 | 真机上漏斗事件能在后台看到，字段完整 |

## G5 软启动 / 买量验证

目的：用小预算验证 **LTV > CPI** 是否可能成立，而不是追求规模。先选 1–2 个代表市场，小预算（常见几百到几千美元量级，按品类）投 1–2 周。

| 指标 | 超休闲参考 | 休闲/混合参考 | 中度参考 |
|---|---|---|---|
| CPI | < $0.3（视地区） | $0.5–1.5 | $2–5 |
| D1 留存 | ≥ 35% | ≥ 35–40% | ≥ 38–42% |
| D7 留存 | ≥ 8% | ≥ 12–15% | ≥ 15–20% |
| D30 留存 | — | ≥ 4–6% | ≥ 7–10% |
| 人均会话时长/日 | ≥ 8 分钟 | ≥ 15 分钟 | ≥ 25 分钟 |
| 广告每 DAU 展示（IAA） | ≥ 6–10 | ≥ 4–8 | — |
| ARPDAU | ≥ $0.08 | $0.05–0.20 | $0.15–0.5+ |
| 付费转化（IAP） | — | ≥ 1.5–3% | ≥ 3–5% |

核心判断：
- **预测 D7 LTV ≥ CPI × 1.1–1.3**（含渠道分成和成本），回本周期可接受 → 放量。
- LTV 靠 ARPDAU × 预期生命周期估算：`LTV ≈ ARPDAU × Σ(留存_d)`；用 D1/D7/D30 拟合留存曲线（幂函数）外推，并写明置信区间。
- 样本量：每个变体至少数百到上千安装才有意义，样本不够只写"方向性"。

不通过的分流：

| 症状 | 原因假设 | 动作 |
|---|---|---|
| CPI 高，留存好 | 素材/商店页/定位 | 换素材 A/B，改图标/截图；留存好值得继续 |
| CPI 低，D1 差 | 素材与实际玩法不符，或新手期差 | 改素材真实度 + 新手引导 |
| D1 好，D7 差 | 中期内容/目标不足 | 回 G3 改成长与每日循环 |
| 留存好，ARPDAU 低 | 变现点少或位置差 | 调广告点位/付费点，不要砍留存 |

## G6 上线与运营

| 检查项 | 通过标准 |
|---|---|
| 合规清单 | 全绿或有明确豁免记录（`monetization-compliance.md`） |
| 商店页 | 图标/截图/描述/隐私政策/分级问卷完成 |
| 发布 | 对外分发由人执行；所有权确认见 `rebuild-build-release` G-PUBLISH |
| 回滚与热修 | 上一版本包保留；配置可远程开关（广告开关、难度参数） |
| 监控 | 崩溃/ANR 看板、关键漏斗、收入看板 |
| 运营日历 | 首月每周有内容或活动 |
| keystore | 双人双地备份（见 `rebuild-build-release`） |
