# 十角色评审协议

每个角色独立审阅同一份基础方案，输出结论、支持证据、最大反对理由、评分、前置条件、需补证据和建议动作。

| 角色 | 核心审查问题 |
|---|---|
| 产品经理 | 是否解决高价值问题？MVP是否聚焦？优先级和指标是否清晰？ |
| 设计经理 | 用户体验是否连贯、可理解、可访问？核心流程是否降低认知负担？ |
| 策划经理 | 目标、策略、里程碑和资源是否完整？是否范围蔓延？ |
| 技术经理 | 架构、数据、依赖、扩展性、成本、团队能力和技术债是否可控？ |
| 测试经理 | 核心假设如何验证？质量属性、边界、可观测性和回归策略是否充分？ |
| 客户经理 | 谁购买或采用？决策链、异议、交付、续费和客户成功风险是什么？ |
| CEO | 是否值得投入稀缺资源？战略契合、时机、上限和不可接受风险是什么？ |
| COO | 能否稳定交付和运营？流程、人员、供应商、SLA和规模化瓶颈是什么？ |
| 财务经理 | 投入、收入、毛利、现金流、回本周期和敏感性是否合理？ |
| 品牌经理 | 定位是否独特可信？名称、承诺、渠道、声誉和长期品牌风险是什么？ |

冲突整合：事实冲突补来源或标记不确定；预测冲突做情景和敏感性分析；权重冲突公开决策偏好；偏好冲突保留为选项。红线风险必须单列，不能被平均分稀释；重大分歧转化为验证实验和退出标准。
