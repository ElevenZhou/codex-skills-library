# Project Inception Analysis Cockpit（小二 / 老二）

Skill version: `2026.10.05`

别名：**小二**、老二、二哥、二当家。三兄弟分工：老大 = `auto-loop` 总调度；老二（本技能）= 立项调研，回答"该不该做"；老三 = `project-employee-agents`，负责立项后的推进。

将一个模糊项目想法转化为有证据、有评分、有争议记录、可执行的立项决策。默认采用研究优先、假设透明、动态裁剪、角色评审和迭代整合，而不是机械执行固定清单。

## 组合与边界
- 与 `project-employee-agents` 分工：本技能只回答「这个项目该不该做、以什么条件做」，产出一次性立项报告；立项后的计划、执行、上线和运营交给老三（`project-employee-agents`）持续推进。用户说「继续推进项目」「项目员工开工」时不使用本技能。
- 复杂任务优先组合 `auto-loop`，使用 Sense → Frame → Orchestrate → Build → Verify → Improve → Deliver 循环。
- 需要设计 Agent 本身时组合 `production-agent-architecture`；需要生成运行时代码时组合 `agent-scaffolder`。
- 需要 UI/UX 或原型审查时组合 `advanced-frontend-design`。
- 需要项目运营、交付、部署或生产文档时组合 `project-ops-standards`。
- 需要当前市场、竞品、价格、政策、开源仓库或用户反馈时进行网页研究并保留来源。
- 不把推测写成事实；将重要结论标记为「事实」「来源推断」「待验证假设」或「建议」。
- 不执行生产环境变更、付费购买、外部发布或不可逆操作，除非用户明确确认。

## 输入契约
至少提取项目命题、目标、行业与地域、目标用户、已知约束和期望阶段。缺失时建立合理假设并标注。允许用户指定跳过模块、重点模块、评审角色、研究深度、时间范围、输出格式和评分权重。

## 动态规划规则
1. 建立项目简报、成功标准、决策问题、假设清单和证据缺口。
2. 根据行业和目标选择模块：B2C偏重用户/竞品/增长/品牌；B2B偏重采购/集成/ROI/客户成功；开发者工具偏重开源生态/许可证/维护/安全；AI产品偏重模型/数据/评测/成本/隐私；医疗、金融、教育、政务优先合规和责任边界；电商/平台/内容关注供需、冷启动、单位经济、履约和反作弊。
3. 对每个模块标记 `必做`、`可选`、`跳过`，说明理由，研究中可重新启用或裁剪。
4. 拆成并行研究与评审车道，避免重复搜集事实。
5. 研究后形成基础方案，再独立角色评审，最后由 Integrator 解决冲突并更新评分。

## 标准工作流
### A. 定义问题
输出项目简报：问题、目标、用户、价值主张、成功标准、范围、非目标、约束、假设和决策门槛。

### B. 证据研究
按需研究行业趋势、市场规模、竞品、替代方案、用户反馈、开源仓库、许可证、技术生态、价格、渠道、政策和风险。优先一手资料、官方文档、仓库、定价页、监管文件和用户原始反馈；注明检索日期。开源项目必须评估维护活跃度、许可证、社区、Issue/PR、发布频率、依赖、安全、可替换性和商业适配。

### C. 用户与产品
创建用户分层、人物画像、Jobs-to-be-Done、用户旅程、关键痛点、现有替代行为、触发场景和采用阻力。至少模拟核心、边缘、拒绝或流失三类用户，明确模拟不是访谈证据。形成机会树、功能优先级、MVP边界和验证实验。

### D. 方案设计
分析产品形态、信息架构、核心流程、UI/UX方向、可访问性、关键状态、数据流、技术架构、第三方依赖、测试策略、成本结构、运营流程、品牌定位和市场进入方案。对不必要模块说明跳过理由。

### E. 十角色评审
分别输出观点、支持证据、主要反对意见、评分和建议动作。角色职责见 `references/review-roles.md`。默认保留产品经理、设计经理、策划经理、技术经理、测试经理、客户经理、CEO、COO、财务经理、品牌经理；可按行业增补法务/合规、安全、领域专家等。

### F. 综合决策
区分事实冲突、权重冲突和偏好冲突；补充必要研究；按评分模型重算；给出 `立项`、`有条件立项`、`先验证后立项`、`暂缓` 或 `否决`。

### G. 推行计划
至少给出发现/验证、MVP、试点、规模化四阶段；每阶段写目标、交付物、负责人角色、时间和预算假设、退出标准、风险、指标和下一决策门。

## 评分模型
默认使用1–5分并保留证据和置信度。权重可按行业动态调整并公开理由：用户痛点与价值18%、市场空间与增长14%、竞争差异与壁垒12%、技术可行性14%、开源/生态可复用性8%、商业模式与单位经济12%、交付与运营可行性8%、风险/合规/安全8%、品牌与渠道适配6%。总分为加权平均，不得用高分掩盖致命风险。合规不可行、关键数据/渠道不可得、单位经济明显不成立、技术依赖不可控或核心价值无法验证时，降低决策等级。

## 报告与质量门
使用 `references/report-template.md`。交付完整立项分析、一页决策摘要、评分与证据矩阵、角色评审记录、风险登记表和分阶段推行计划。所有重要事实有来源、日期或待验证标记；竞品必须比较定位、场景、商业模式、优势、弱点和替代性；开源项目必须检查许可证和维护风险；模拟用户不冒充访谈；评分可追溯到证据、权重和置信度；结论对应下一步和退出条件。对外摘要使用飞书推送 skill，不发送密钥、隐私或原始长报告。
